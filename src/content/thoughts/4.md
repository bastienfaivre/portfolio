title: "Git-inspired LLM"
date: 2026-07-26
---

I often have deep, long discussions with LLMs, and most of them lead to the same structure where each message carries many subtopics:

```
LLM:
├── Subtopic 1
├── Subtopic 2
├── ...
└── Subtopic N

                 Me:
        Answer 1 ──┤
        Answer 2 ──┤
             ... ──┤
        Answer N ──┘
```

The problem is that, sometimes, for some subtopics, I want to go deeper and explore them further without polluting the main thread of the conversation. I want to be able to branch off into a subtopic, explore it in depth, and then return to the main discussion without losing context.

This is the same as Git, where the side conversations are branches, and returning to the main discussion is like merging back into the main branch, the final result of the investigation.

If, by reading this, you are thinking, "It is so easy to build it, I will do it right now and try to monetize it as a SaaS!", please don't. Why? This is exactly the topic of the next thought.

In the meantime, touch some grass and breathe some fresh air.
